# 0004 — react-native-maps behind an adapter, MapLibre later

**Status:** Accepted

## Context

The map is the main screen. Options: `react-native-maps` (Apple Maps on iOS with no key; Google Maps on Android, which needs an API key) or MapLibre (open tiles, offline regions, no Google dependency, but more setup and a tile source to choose).

## Decision

Start with `react-native-maps` (Phase 2) behind a single `MapLayer` component with platform files, so the rest of the app never imports the library. Clustering with `supercluster` in JS on the points of the current viewport; markers memoized with `tracksViewChanges={false}`.

## Consequences

- Fast to ship and familiar; iOS contributors need no key.
- Android contributors need a Google Maps key, documented in `.env.example` when Phase 2 lands.
- Migrating to MapLibre later (open data, offline regions) touches `MapLayer` and its tests only.
